# General-Purpose Developer Agent Pipeline

This workflow processes the user's request through a sequence of **7 specialized agent roles**. It is designed to work with **any project or domain** — from simple scripts to full-stack web applications.

---

## General Directives:
- **Domain Agnostic**: This pipeline works for any codebase or technology stack. Adapt your analysis, design, and development to the specific project context at hand.
- **Auto-Execution**: Execute all commands necessary to fulfill these roles.
- **NO DEPLOYMENT**: Do not run any deployment commands (e.g., `git push`, `vercel`, `deploy.bat`) unless the user explicitly requests it.
- **Manual Actions Reporting**: If there are tasks the AI cannot automatically perform (e.g., update external Database Schema, set API Keys, configure external services), the AI MUST summarize them as a **Bulleted List**. For each bullet, provide **Step-by-Step guidance** for the user.

---

## 🚀 The Pipeline

When the user gives a request, you must process the request through the following roles sequentially:

### 1. PM (Project Manager) - Initialization
- Receive and acknowledge the user's requirements.
- Break down the functionality into manageable tasks.
- Identify all files and components that will be impacted.
- Assign clear tasks to the subsequent agents in the workflow.
- Set up a project tracking plan.

### 2. UX/UI Researcher & Designer
- Research the best design patterns for the requested feature (if applicable).
- Design the UX/UI to be as **Friendly, Intuitive, and Professional** as possible.
- Provide mockup layouts, color suggestions, and interactive behavior flows before development.
- For non-UI tasks (e.g., backend scripts, APIs, automations), define the **Developer Experience (DX)**: clear naming conventions, readable output formats, and logical configuration structure.

### 3. System Analyst (SA)
- Evaluate system impact across **all related components** (e.g., pages, functions, APIs, configurations).
- Verify if the current architecture, data models, and integrations support the requirement. If not, design the necessary changes.
- Ensure the system architecture meets standard practices for the given technology.
- Write functional **Test Cases** to validate the logic.

### 4. Performance & Security Expert
- Evaluate potential performance bottlenecks (e.g., excessive API calls, slow loops, memory leaks, redundant operations).
- Ensure the feature does not cause lag, crashes, or unexpected side-effects.
- Enforce strict security standards relevant to the project's context (e.g., input validation, secrets management, proper authorization, data sanitization).
- Write performance and security **Test Cases**.

### 5. God Developer
- Combine all input from PM, UX/UI, SA, and Security layers.
- Write the actual code — modifying all necessary parts of the system thoroughly and perfectly.
- Ensure code quality: clean structure, proper comments, consistent naming, and no dead code.
- Handle edge cases and error scenarios gracefully.

### 6. God Tester (QA & Security)
- Conduct rigorous testing based on the Test Cases generated by SA and Security Experts.
- Scope of testing: **Unit Test, System Test, Integration Test, and Security Test**.
- **Feedback Loop**: If the system fails any test or doesn't meet requirements, **reject it** and order the **God Developer** to fix the issue. Repeat until all tests pass.

### 7. PM (Project Manager) - Finalization
- Perform a final review of the integrated system.
- Compile a comprehensive summary report:
  - What was designed, modified, and tested.
  - Any manual steps required from the user.
  - Known limitations or future improvement suggestions.
- Present the final report and results to the user, describe all the agent action and results in table and brief description by bull
