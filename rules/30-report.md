# 6. รูปแบบการรายงานผล (บังคับทุกครั้งที่จบงาน)

ตอบเป็นภาษาไทย โค้ด คอมเมนต์ และชื่อตัวแปรเป็นภาษาอังกฤษ

ผู้อ่านคือผู้บริหารที่มีเวลาน้อย เขียนแบบเลขาฯ ของ CEO: อ่านจบใน 30 วินาที
รูปแบบนี้ ("bullet + ตารางตัดสินใจ") ใช้กับทุกโครงการ ตามลำดับนี้:

```
**ผล:** <คำตัดสินหนึ่งบรรทัด: เสร็จ/ไม่เสร็จ ใช้ได้/ใช้ไม่ได้ — ข่าวร้ายอยู่ตรงนี้>

- <เรื่องที่ผู้ใช้สั่ง ใช้เลขข้อของผู้ใช้> — <ทำแล้ว / ไม่ได้ทำ / ใช้ไม่ได้> (<ผลรันย่อ: tsc 0 error · test 16/16 · HTTP 200 · ก่อน 7 → หลัง 0>)
- **สมมติฐาน:** <ค่าที่เลือกแทนผู้ใช้>
- **ยังไม่ได้ตรวจ / ยังไม่ได้ทำ:** <อะไร + เพราะอะไร>

**ต้องการให้ตัดสินใจ**

| ข้อ | เรื่อง | ตัวเลือก | ผลกระทบ / ความเสี่ยง | แนะนำ |
|---|---|---|---|---|
| 1 | <ต้องตัดสินใจอะไร และทำไมต้องตอนนี้> | A: <...> · B: <...> | A: <ได้อะไร เสียอะไร> · B: <...> | A — <เหตุผลหนึ่งประโยค> |

ตอบสั้นๆ ได้ เช่น "1A"
```

bullet **สมมติฐาน** / **ยังไม่ได้ตรวจ** และตาราง **ต้องการให้ตัดสินใจ** ใส่เฉพาะเมื่อมี
แต่ถ้ามีสิ่งที่ไม่ได้ทำหรือไม่ได้ตรวจ ต้องเขียนเสมอ (ห้าม fallback เงียบ)
ถ้าไม่มีเรื่องให้ตัดสินใจ ไม่ต้องมีตาราง

## กฎการเขียน

- ส่วนผลลัพธ์เป็น **bullet** ไม่เกิน 8 ข้อ ข้อละหนึ่งบรรทัด รวมเรื่องย่อยเป็นข้อเดียว ห้ามหัวข้อย่อย ห้าม bullet ซ้อน
- หลักฐานในวงเล็บต้องมาจากผลรันจริง ย่อเป็นตัวเลข ห้ามแปะ log ทั้งก้อน
- **ตารางมีไว้สำหรับเรื่องที่ผู้ใช้ต้องตัดสินใจเท่านั้น** หนึ่งแถวต่อหนึ่งเรื่อง เรียงตามความเร่งด่วน
  ทุกแถวต้องมีตัวเลือก ผลกระทบของแต่ละตัวเลือก และตัวที่แนะนำพร้อมเหตุผล ให้ผู้ใช้ตอบได้ในคำเดียว
- งานเล็กที่ไม่มีอะไรให้เทียบ: บรรทัด **ผล** + หลักฐานในวงเล็บ ก็พอ
- ไม่เล่ากระบวนการ ไม่อธิบายวิธีคิด ไม่ทวนคำสั่ง ไม่มีคำเกริ่นหรือคำปิดท้าย
- รายละเอียด และเหตุผลยาวๆ ให้เมื่อผู้ใช้ถาม หรือเขียนลงไฟล์แล้วใส่ลิงก์
- ไฟล์ที่อ้างถึง ให้เขียนเป็น markdown link ที่คลิกได้ พร้อมเลขบรรทัดถ้ามี
- คำสั่งที่ผู้ใช้ต้องรัน ใส่ใน code block ภาษา `bash` แยกก้อนละหนึ่งคำสั่ง

# 7. ทำเองให้จบ อย่าโยนขั้นตอนกลับไปให้ผู้ใช้

ถ้าทำเองได้ ให้ทำ อย่าเขียนคู่มือให้ผู้ใช้ไปกดเอง
สิ่งที่ทำเองไม่ได้จริงๆ ให้ใส่ใน bullet **ยังไม่ได้ทำ** พร้อมเหตุผลว่าทำไมถึงทำไม่ได้

# 8. ข้อจำกัดของ Windows (เครื่องนี้)

- `npx` `npm` และ `.cmd` shim อื่นๆ spawn ตรงๆ ไม่ได้ ต้องผ่าน shell
  หรือเรียก JS entry point ของ package ผ่าน `node` แทน
- heredoc ทำให้ backslash เพี้ยน — regex และ path ของ Windows ให้เขียนด้วย
  เครื่องมือแก้ไฟล์ ไม่ใช่ pipe สคริปต์เข้า bash
- ตั้ง `PYTHONIOENCODING=utf-8` ก่อนรัน Python ที่พิมพ์ภาษาไทย
- ไฟล์ต้นฉบับอาจเป็น UTF-16 ให้อ่านแบบเผื่อไว้แล้วแปลงเป็น UTF-8
