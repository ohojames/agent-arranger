# 6. รูปแบบการรายงานผล (บังคับทุกครั้งที่จบงาน)

ตอบเป็นภาษาไทย โค้ด คอมเมนต์ และชื่อตัวแปรเป็นภาษาอังกฤษ

ผู้อ่านคือผู้บริหารที่มีเวลาน้อย เขียนแบบเลขาฯ ของ CEO: อ่านจบใน 15 วินาที
งานของเลขาฯ คือ **คัดทิ้ง** ไม่ใช่ย่อ — สิ่งที่ทำไปแล้วและเป็นไปตามที่สั่ง ผู้ใช้ไม่ต้องรู้

## คัดก่อนเขียน

รายงานเฉพาะสิ่งที่ผ่านอย่างน้อยหนึ่งข้อ:

1. ผลไม่ตรงกับที่สั่ง หรือมีข่าวร้าย
2. ยังไม่ได้ทำ หรือยังไม่ได้ตรวจ (ห้าม fallback เงียบ)
3. ผู้ใช้ต้องลงมือทำเอง หรือต้องตัดสินใจ
4. สิ่งที่ผู้ใช้จะเข้าใจผิดถ้าไม่บอก (เช่น ค่าที่เลือกแทนผู้ใช้ หรือมีผลเมื่อไร)

ไม่ผ่านเลยสักข้อ = ตัดทิ้ง ได้แก่ รายชื่อไฟล์ที่แก้ จำนวนไฟล์/โปรเจกต์ ผลเทสต์ทีละชุด
ขนาดไฟล์ commit hash skill ที่ใช้ และสิ่งที่ทำตามคำสั่งเป๊ะๆ
หลักฐานที่ยืนยันคำตัดสิน ใส่ **ชิ้นเดียวที่สำคัญที่สุด** ในวงเล็บท้ายบรรทัด **ผล**

## รูปแบบ

```
**ผล:** <คำตัดสินหนึ่งบรรทัด — ข่าวร้ายอยู่ตรงนี้> (<หลักฐานชิ้นเดียว>)

- <เฉพาะเรื่องที่ผ่านเกณฑ์ข้างบน หนึ่งบรรทัด>

**ต้องการให้ตัดสินใจ**

| ข้อ | เรื่อง | ตัวเลือก | ผลกระทบ / ความเสี่ยง | แนะนำ |
|---|---|---|---|---|
| 1 | <ต้องตัดสินใจอะไร> | A: <...> · B: <...> | A: <ได้อะไร เสียอะไร> · B: <...> | A — <เหตุผลหนึ่งประโยค> |
```

- bullet **ไม่เกิน 3 ข้อ** ปกติ 0–2 ถ้าไม่มีอะไรผ่านเกณฑ์ ให้มีแค่บรรทัด **ผล**
- ตารางใส่เฉพาะเรื่องที่คำตอบเปลี่ยนสิ่งที่จะทำต่อ ไม่เกิน 3 แถว เรียงตามความเร่งด่วน
  ทุกแถวมีตัวเลือก ผลกระทบ และตัวที่แนะนำ ให้ตอบได้ในคำเดียว (เช่น "1A")
- เรื่องที่ค้างจากงานก่อนและผู้ใช้ยังไม่ตอบ ไม่ต้องยกมาถามซ้ำทุกรอบ

## กฎการเขียน

- ห้ามหัวข้อย่อย ห้าม bullet ซ้อน ห้ามแปะ log
- ไม่เล่ากระบวนการ ไม่อธิบายวิธีคิด ไม่ทวนคำสั่ง ไม่มีคำเกริ่นหรือคำปิดท้าย
- รายละเอียดให้เมื่อผู้ใช้ถาม หรือเขียนลงไฟล์แล้วใส่ลิงก์
- ไฟล์ที่อ้างถึง ให้เขียนเป็น markdown link ที่คลิกได้ พร้อมเลขบรรทัดถ้ามี
- คำสั่งที่ผู้ใช้ต้องรัน ใส่ใน code block ภาษา `bash` แยกก้อนละหนึ่งคำสั่ง

# 7. ทำเองให้จบ อย่าโยนขั้นตอนกลับไปให้ผู้ใช้

ถ้าทำเองได้ ให้ทำ อย่าเขียนคู่มือให้ผู้ใช้ไปกดเอง
สิ่งที่ทำเองไม่ได้จริงๆ ให้ใส่ใน bullet **ยังไม่ได้ทำ** พร้อมเหตุผลว่าทำไมถึงทำไม่ได้

# 8. ข้อจำกัดของ Windows (เครื่องนี้)

- `npx` `npm` และ `.cmd` shim อื่นๆ spawn ตรงๆ ไม่ได้ ต้องผ่าน shell
  หรือเรียก JS entry point ของ package ผ่าน `node` แทน
- heredoc ทำให้ backslash เพี้ยน — regex และ path ของ Windows ให้เขียนด้วย
  เครื่องมือแก้ไฟล์ ไม่ใช่ pipe สคริปต์เข้า bash
- ตั้ง `PYTHONIOENCODING=utf-8` ก่อนรัน Python ที่พิมพ์ภาษาไทย
- ไฟล์ต้นฉบับอาจเป็น UTF-16 ให้อ่านแบบเผื่อไว้แล้วแปลงเป็น UTF-8
