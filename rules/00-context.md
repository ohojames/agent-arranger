# 1. รู้ว่ากำลังทำงานในนามใคร ก่อนแตะอะไรที่ออกนอกเครื่อง

เครื่องนี้มี GitHub / Supabase / Vercel หลายบัญชี การใช้ผิดบัญชีไม่ได้พังทันที
แต่จะเงียบไปจนกระทั่ง push ไม่ขึ้น หรือ deploy ไปโปรเจกต์ผิด

- ทุกเทิร์นจะมีบล็อก `<project-context>` ฉีดเข้ามาให้ อ่านมันก่อนเสมอ
  ถ้าบล็อกนั้นบอกว่า `MISMATCH` ให้หยุดและแก้บัญชีก่อน ห้าม push
- คำสั่งที่สลับบัญชีได้: `gh auth switch --hostname github.com --user <ชื่อ>`
- ห้ามเดาบัญชีจากชื่อโฟลเดอร์ ให้ดูจาก `git remote -v` ของ repo นั้นเป็นหลัก
- ห้ามเขียน token หรือ key ลงไฟล์ ลงสคริปต์ หรือลงคำสั่งที่ถูกบันทึกใน log
  อ่านจาก environment variable เท่านั้น

# 2. ห้ามเปลี่ยน environment เงียบๆ

ก่อน deploy หรือก่อนรันอะไรที่แตะฐานข้อมูลจริง:

1. เทียบตัวแปร environment ของปลายทางกับของเครื่อง — ปลายทางที่ชี้ผิดฐานข้อมูล
   จะสตาร์ตได้ปกติและไม่ฟ้องอะไรเลย
2. ตรวจว่า auth redirect allow-list ครอบคลุมทุก origin ที่ app ถูกเสิร์ฟ
   รวม preview URL ด้วย (preview hostname เปลี่ยนทุก build ให้จับด้วย pattern)
3. ส่ง production URL ที่เสถียรให้ผู้ใช้ ไม่ใช่ preview URL ของ build นั้น
