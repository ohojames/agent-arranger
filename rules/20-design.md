# 5. กฎการออกแบบหน้าจอ (บังคับทุกหน้าและทุก dialog ที่แตะ)

สาเหตุที่หน้าเว็บที่ AI ทำออกมาดู "มือสมัครเล่น" ไม่ใช่เพราะสีไม่สวย
แต่เพราะ **ค่าที่ใช้มันมั่ว** — ระยะห่าง 7 ค่าในหน้าเดียว ตัวอักษร 6 ขนาด
เทา 5 เฉด ทุกอย่างเลยดูเท่ากันหมดและไม่มีลำดับสายตา

กฎข้างล่างนี้ตรวจได้ด้วยตา ไม่ใช่ความรู้สึก ถ้าฝ่าฝืนคือ defect

## 5.1 บันไดค่าที่ใช้ได้ — ห้ามใช้ค่านอกรายการ

| เรื่อง | ใช้ได้เฉพาะ | ห้าม |
|---|---|---|
| ระยะห่าง (gap, p-, m-, space-) | `1 2 3 4 6 8 12 16` | `5 7 9 10 11 13 14 15` และค่า arbitrary `[13px]` |
| ขนาดตัวอักษร | `text-xs` `text-sm` `text-base` `text-lg` `text-2xl` | `text-md` `text-xl` `text-3xl` ขึ้นไป (ยกเว้นตัวเลขใหญ่ใน KPI card) |
| น้ำหนักตัวอักษร | `font-normal` `font-medium` `font-semibold` | `font-bold` `font-light` `font-black` |
| ความโค้งมุม | `rounded-md` สำหรับทุกอย่าง, `rounded-full` เฉพาะ avatar/badge | `rounded-sm` `rounded-xl` ปนกันในหน้าเดียว |
| เงา | `shadow-sm` เท่านั้น สำหรับ card ที่ต้องแยกจากพื้น | `shadow-lg` `shadow-xl` บนของที่ไม่ลอย |
| เส้นขอบ | `border-gray-200` | เส้นหลายเฉดในหน้าเดียว |

**เทาใช้ได้ 4 ระดับเท่านั้น** และแต่ละระดับมีหน้าที่ตายตัว:

| คลาส | ใช้กับ |
|---|---|
| `text-gray-900` | ข้อความหลัก ตัวเลขที่ต้องอ่าน |
| `text-gray-500` | label, คำอธิบาย, หน่วย, วันที่ |
| `border-gray-200` | เส้นคั่น ขอบ card ขอบ input |
| `bg-gray-50` | พื้นหลังหัวตาราง แถบสลับสี พื้นที่ disabled |

## 5.2 ลำดับสายตา — หนึ่งหน้ามีพระเอกได้คนเดียว

- หัวข้อหน้า **หนึ่งอัน** `text-2xl font-semibold` และต้องใหญ่กว่าทุกอย่างชัดเจน
- ใต้หัวข้อมีคำอธิบายหนึ่งบรรทัด `text-sm text-gray-500` เสมอ
- ปุ่มหลัก **หนึ่งปุ่มต่อหนึ่งหน้า/หนึ่ง dialog** ที่เหลือเป็นปุ่มรอง
- ถ้าทุกอย่างในหน้าเด่นเท่ากัน แปลว่าไม่มีอะไรเด่น — ต้องลดของอื่นลง

## 5.3 ที่ว่าง

- ระยะห่างระหว่าง "กลุ่มของเนื้อหา" ต้องมากกว่าระยะห่างภายในกลุ่มเสมอ
  (ภายในกลุ่มใช้ `gap-2`/`gap-3` ระหว่างกลุ่มใช้ `gap-6`/`gap-8`)
  ถ้าสองค่านี้เท่ากัน สายตาจะจับกลุ่มไม่ได้ และหน้าจะดูเละ
- ห้ามยัดของชิดขอบ card — ใช้ `p-4` เป็นอย่างน้อย
- แถวในฟอร์มเรียง label บนสุด แล้ว input ข้างล่าง ห้ามสลับไปมาในหน้าเดียวกัน

## 5.4 ตาราง

- หัวตาราง `bg-gray-50 text-xs font-medium text-gray-500` ตัวพิมพ์ปกติ ไม่ต้องหนา
- แถวสลับพื้นหลัง และเนื้อหากว้างต้องอยู่ใน `overflow-x-auto` ของตัวเอง
- **ตัวเลขชิดขวาเสมอ** ข้อความชิดซ้าย วันที่ชิดซ้าย
- ตัวเลขเงินและจำนวน ใช้ฟอนต์ตัวเลขความกว้างเท่ากัน (`tabular-nums`)
  ไม่งั้นหลักจะไม่ตรงกันและอ่านยอดรวมไม่ได้
- คอลัมน์ action อยู่ขวาสุดเสมอ

## 5.5 สถานะและ feedback

- ทุกอย่างที่โหลดข้อมูลต้องมีครบ 4 สถานะ: กำลังโหลด / ว่าง / ผิดพลาด / มีข้อมูล
  **สถานะ "ว่าง" ต้องบอกว่าให้ทำอะไรต่อ** ไม่ใช่แค่คำว่า "ไม่มีข้อมูล"
- ปุ่มที่ยิง request ต้อง `disabled` ระหว่างรอ และเปลี่ยนข้อความบอกว่ากำลังทำอะไร
- ข้อความ error ต้องบอกว่าผู้ใช้ต้องทำอะไรต่อ ไม่ใช่โยน error ของระบบใส่หน้า

## 5.6 มือถือ

ทุกหน้าต้องใช้งานได้ที่ความกว้าง 375px

- ตารางที่กว้างต้องเลื่อนแนวนอนได้ ไม่ใช่ทำให้ทั้งหน้าเลื่อน
- ปุ่มและสิ่งที่กดได้ ต้องสูงอย่างน้อย 44px
- แถวที่เรียงแนวนอนต้องยุบลงเป็นแนวตั้งเมื่อจอแคบ

## 5.7 ก่อนบอกว่าหน้าเสร็จ — ต้องเปิดดูของจริง

**ห้ามส่งงาน UI โดยไม่เคยเห็นมัน** เขียน JSX แล้วเดาว่าออกมาหน้าตายังไง
คือสาเหตุอันดับหนึ่งของงานที่ดูไม่เรียบร้อย

ลำดับที่ต้องทำ:

1. รัน dev server
2. เปิดหน้านั้นด้วย MCP `chrome-devtools` (หรือ browser tool ที่มี)
3. แคปหน้าจอที่ความกว้าง 1280 และ 375
4. ไล่เช็กกับข้อ 5.1–5.6 ข้างบน แล้วแก้สิ่งที่ผิด
5. เช็ก console ว่าไม่มี error
6. แนบสิ่งที่เห็นในรายงาน

ถ้าเปิดดูไม่ได้ด้วยเหตุผลอะไรก็ตาม **ให้บอกตรงๆ ว่าไม่ได้ดู** อย่าเงียบ

## 5.8 ของที่มีอยู่แล้วในโปรเจกต์ ต้องใช้ ห้ามสร้างใหม่

- ก่อนสร้าง component ใหม่ ให้ดู `src/components/ui/` ก่อนเสมอ
- ก่อนเขียนคลาสสีปุ่มเอง ให้ดูว่าโปรเจกต์มีไฟล์นโยบายปุ่มอยู่แล้วหรือไม่
- ก่อน format วันที่ ให้ดูว่ามี helper กลางอยู่แล้วหรือไม่ ห้ามเรียก
  `toLocaleDateString` ตรงๆ ในหน้า
- หน้าใหม่ต้องลอกโครงจากหน้าที่มีอยู่แล้วในโปรเจกต์ ไม่ใช่คิดโครงใหม่เอง
